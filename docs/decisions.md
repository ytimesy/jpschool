# Design Decisions

重要な設計判断と、その時点の理由を記録します。DB設計、認証、個人情報、配置、外部サービス依存を変更する場合はこのファイルを更新します。

## 2026-09-01: MVPはRails一体型アプリで進める

- 状態: 採用
- 関連: `SPEC.md` 10章
- 判断: MVPではRailsのサーバーサイドレンダリング、PostgreSQL、Hotwire/Turbo/Stimulus、Tailwind CSSを基本構成にする。
- 理由: 1か月MVPでは、認証、DB、画面、管理機能、テストを1リポジトリで扱える構成の方が実装と運用確認を小さく保てるため。
- 影響: SPAと公開JSON APIの分離はMVP対象外。必要になった場合は仕様変更として扱う。

## 2026-09-01: 生成AI会話と発音採点はMVP対象外にする

- 状態: 採用
- 関連: `SPEC.md` 3.3、19章
- 判断: 実行時の生成AI会話、音声認識、発音自動採点はP2に置く。
- 理由: 安全性、評価品質、実機検証、外部サービス管理の負荷が高く、P0の学習・復習・管理機能を圧迫するため。
- 影響: 教材は事前作成した本文、翻訳、音声を使う。
